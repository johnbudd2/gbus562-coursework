# gbus562-coursework

## About

This repository holds the materials created in UMW's GBUS 562 course (AI Language Models). It is organized by weekly folders.

## Weekly Work

1. week-01
   - [Connect 4](week-01/connect4.html): a single-page browser game built with HTML and JavaScript. Play against a computer opponent that looks several moves ahead, with three strength levels, or switch to two-player mode to take turns with a friend on the same screen. It keeps a running score.
2. week-02
   - [Prompt Lab](week-02/prompt-lab.html): a web app for testing prompts against Claude, built with Claude Code.
   - [Exported runs](week-02/runs/): four Prompt Lab runs for the Wildframe tasks, one per prompting technique (zero-shot, one-shot, few-shot, chain-of-thought).
   - [Writeup](week-02/writeup.md): why each technique fit its task, one full example run, and a reflection comparing the results.
3. week-03
   - [ask.py](week-03/ask.py): a RAG tool that answers questions from Copperline Manufacturing's finance documents, built with Claude Code.
   - [Larkfield runs](week-03/runs/): the same overdraft-fee question asked about Larkfield Credit Union's documents [before](week-03/runs/q1-before.txt) and [after](week-03/runs/q1-after.txt) removing a superseded version of the fee schedule, plus five more test questions covering card fees, fraud liability, multi-document refund approval, funds availability, and an out-of-scope question.
   - [Writeup](week-03/writeup.md): what I built, why I chose section-based chunking, one full example run, and a reflection on the superseded fee schedule and the out-of-scope question.
4. week-04
   - Week 4: an AI agent that prepares replies to HR emails using tools from an MCP server, built with Claude Code.
   - [hr_mcp_server.py](week-04/hr_mcp_server.py): the MCP server, with two tools for Hartwell Foods' HR data: `search_policy` (the 4 closest HR document sections, with source files) and `get_leave_balance` (from `employees.csv`, by work email for HR staff, or limited to one employee when started with `--as-employee`).
   - [agent.py](week-04/agent.py): a command-line agent that drafts a reply to one employee email. It starts the MCP server limited to the sender, lets Claude (`claude-sonnet-5`) use its tools, and saves the reply to `week-04/drafts/` with a needs-human-review flag. It never sends anything, and it stops after 10 tool calls. Both scripts take `--org` to point them at another organization's folder (default `hartwell-hr`); the employee file's email and balance columns are worked out from its header row, and each organization gets its own search database. `--save` writes the agent's output to a text file.
   - [ridgeline-hotels](week-04/ridgeline-hotels/): a second organization (Ridgeline Hotels) with its own HR documents, employee file, sample emails, and system prompt, used to test the agent on a different company.
   - [Ridgeline runs](week-04/runs/): the agent's saved output for all seven Ridgeline sample emails, covering a PTO question, bereavement leave, a honeymoon longer than the PTO balance (run [before](week-04/runs/ridgeline-03.txt) and [after](week-04/runs/ridgeline-03-after.txt) adding a carry-over rule to the system prompt), a request for a coworker's balance, an email with an injected "admin override", a harassment report, and a sender with no employee record.
   - [Writeup](week-04/writeup.md): what I built, whether three Ridgeline tasks need a script, one model call, or an agent, one full example run, and a reflection on the Email 3, 6, and 7 runs.
5. week-05
   - Week 5: a team of AI agents that prepares a bicycle maker's response to supplier emails, built with Claude Code.
   - [supply_mcp_server.py](week-05/supply_mcp_server.py): an MCP server with three read-only tools over Brookfield's CSV files: `get_part` (stock on hand, scheduled shipments, and the models that use the part), `get_orders_for_part` (open orders with units needed, ship day, and late penalty), and `check_coverage` (replaces a part's scheduled shipments with a new arrival list and fills orders complete in ship-day order, returning covered, or units short and the first day each order can ship).
   - [specialists.py](week-05/specialists.py): the four specialists both coordinators share (`claude-sonnet-5`, prompts read from `brookfield-bikes/prompts` on every run): a supply analyst agent that uses the MCP server's tools (at most 10 tool calls) and returns a JSON brief, a supplier-reply writer that never sees customer names, a customer-notice writer given only one order's facts, and a reviewer. Each draft is reviewed and revised at most twice, checked in code for customer names (supplier drafts) or supplier names (customer drafts), and saved to `week-05/drafts/` with a needs-a-person flag. Every handoff and each specialist's tokens are printed.
   - [pipeline.py](week-05/pipeline.py): coordinator 1, a fixed pipeline for one supplier email (`--email`): the supply analyst, then a customer notice for each order at risk (skipped if none), then the supplier reply, each through the review step. It ends with a summary of drafts saved, drafts marked for a person, decisions for a person, and total tokens. `--save` writes everything printed to a text file.
   - [orchestrator.py](week-05/orchestrator.py): coordinator 2, where Claude (`claude-sonnet-5`, with `prompts/orchestrator.txt`) chooses the specialists through four tools: `run_supply_analyst`, `draft_supplier_reply`, `draft_customer_notice` (one order ID, which must be in the analyst's orders at risk), and `finish` (a summary and whether a person must decide). Drafts go through the same review step. It stops after 10 tool calls, prints each choice, and ends with the same summary as the pipeline. Same `--email` and `--save` options.
   - Any company: all four scripts take `--org <company folder>` (default `brookfield-bikes`) and read that company's CSV files and specialist prompts. Drafts are saved in `week-05/drafts/<company folder>/`. The analyst's brief is printed in full, and each final draft is printed after its review step with whether it is marked for a person. `python week-05/specialists.py --org <folder>` checks a company folder without calling the API.
   - [org.py](week-05/org.py): finds a company folder, reads the company name from its prompts, and works out from each CSV header row which column holds the product, quantity, parts per unit, ship day, and so on, so companies can name their columns differently.
   - [copperline-coffee](week-05/copperline-coffee/): a second company (Copperline Coffee Machines) with its own CSV files (different column names from Brookfield's), supplier emails, and prompts.
   - [Copperline runs](week-05/runs/): all four Copperline emails run through both coordinators (`copperline-01-pipeline.txt`, `copperline-01-orchestrator.txt`, ... `copperline-04-orchestrator.txt`): a partial shipment, a choice between two shipping options, a short delay that puts no order at risk, and a notice that needs no action.
   - [Writeup](week-05/writeup.md): what I built and changed for Copperline, whether four Copperline tasks need a script, one model call, an agent, or a team (and a pipeline or an orchestrator), one full example run, and a reflection on the Email 1 and Email 4 runs.
6. week-06
   - Week 6: a service desk assistant for Alder Creek Heating & Cooling, built with Claude Code.
   - [alder-creek](week-06/alder-creek/): the assistant's system prompt, the service desk guide, and test cases.
   - [assistant.py](week-06/assistant.py): a command-line tool that sends one customer service request (`--request "..."`) to Claude (`claude-opus-5-5`) with `assistant-prompt.txt` followed by `service-guide.md` as the system prompt, and prints the JSON reply (`priority`, `reply`, `needs_person`). Two guardrails run in code: a request that mentions gas, carbon monoxide, smoke, or a burning smell never reaches Claude and gets a fixed Safety reply with `needs_person` true; and a reply with a dollar amount not in the guide, "booked" or "confirmed", a clock time, or "covered"/"under warranty" is held (`needs_person` set to true, with a `held_because` field giving the reason).
   - [evaluate.py](week-06/evaluate.py): runs every row of `alder-creek/test-cases.csv` through the assistant and checks each reply in code: the priority matches, the reply has at least one `must_say` phrase and no `must_not_say` phrase (ignoring capital letters), `needs_person` is true where the CSV says yes, and every dollar amount is $0, $89, $149, or $129. It prints PASS or FAIL with reasons for each case and the number passed. `--save <file>` also writes the output to a file.
   - [Evaluation runs](week-06/runs/): `eval-1.txt` (assistant only), `eval-2.txt` (after adding the two code guardrails), and `eval-3.txt` (after changing T6's `must_not_say` phrases, which had matched compliant replies such as "only the warranty team can confirm whether it is covered").
7. capstone
   - [CDI Query Assistant](capstone/README.md): my GBUS 562 capstone. A Claude agent that reviews synthetic inpatient discharge summaries, finds clinical documentation that supports an uncaptured CC or MCC (using RAG over the ICD-10-CM Official Guidelines and exact lookups in the CMS CC/MCC table), and drafts non-leading physician queries for a CDI specialist to review. It includes run logging, a 24-case synthetic evaluation set with an answer key, an evaluation harness, a cost estimator, and a writeup.
